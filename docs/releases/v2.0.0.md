# 🛠️ v2.0.0 – Moderation, Observability & Platform Upgrade

## Overview
This release builds on the v1.0.0 launch of **The Dozens API** with a full **moderation workflow** for submitted insults, **audit history** on content changes, **transactional email** for contributors, and stronger **observability and security** across the stack.

The platform also moves to **Django 6.0 on Python 3.14**, switches dependency management from Poetry to **uv**, and adds a ready-to-use **dev container** for local development.

This is a **major version** because it includes breaking changes to the admin URL, metrics authentication, insult visibility, the required runtime, and environment variable names. See [Breaking Changes](#-breaking-changes) and [Migration Notes](#-migration-notes) before upgrading.

---

## ✨ Features
- **Insult review workflow**: admins can approve, modify, or reject submissions from the admin site (new "Modify" admin view)
  - New fields on `Insult`: `is_admin_modified`, `modified_content`, `reviewer_notes`
  - Contributors get an email when their submission is reviewed, including the outcome and any reviewer notes
  - Review notifications are sent only after the database transaction commits, so a rolled-back review never sends an email
- **Audit history** via `django-simple-history` for `Insult` and `InsultReview`: every change records who made it and when
- **Welcome email** for new users, plus an admin action to resend it
- **Branded HTML email templates** (welcome and submission review) that load fonts and images from a configurable asset base URL
- **Stricter submission validation**: `CreateInsultSerializer` now checks content format before accepting a submission
- **Grafana dashboard** embedded in the admin at `/ops-gateway/observability/`
- **New liveness probe** at `/api/ping/`, separate from the existing `/api/health/` readiness check
- **Versioned, RESTful API routes under `/api/v2.0.0/`**: `GET`/`POST /api/v2.0.0/insults/` (list with `?category=` or create), `/api/v2.0.0/insults/random/`, `/api/v2.0.0/insults/reference-ids/`, `/api/v2.0.0/insults/<reference_id>/`, `/api/v2.0.0/categories/`, `/api/v2.0.0/categories/<category>/insults/`, and `POST /api/v2.0.0/reports/`
  - The old routes still work as deprecated aliases. Their responses carry `Deprecation: true` and `Link: <…>; rel="successor-version"`, and they no longer appear in the OpenAPI schema
- Refreshed templates: registration pages, Swagger UI, ReDoc, GraphiQL, and a custom 404 page

## ⚡ Performance & Optimization
- Fixed a circular import between `common.metrics` and `common.cache_managers` that could slow startup
- Faster cache clearing and more reliable cache invalidation
- Fixed the category list cache key: before, every path-based category shared one cache entry, so `/api/insults/category/poor/` could return results cached for another category
- Optimized regex use in content validation
- Gunicorn: updated worker settings and a liveness probe; the control socket is disabled on macOS to prevent worker crashes

---

## 🛠️ Infrastructure & Observability
- **LaunchDarkly**: feature flags, session replay, and observability plugins on the frontend (`darkly.js`), with hashed context keys and queued event delivery
- **Grafana Loki** log shipping (set `LOKI_URL` / `LOKI_PASSWORD`); the Loki sink no longer crashes on log extras that aren't JSON-serializable
- Logs now use UTC timestamps with millisecond precision, and the LaunchDarkly log handler no longer reports each log twice
- Rebuilt the Grafana overview dashboard to use the metric names Prometheus actually scrapes
- New dev container (`.devcontainer/`) with local Postgres and Redis
- CI: Redis service container for tests, Postgres-backed `Staging` config, coverage reported to Codacy, a tuned Codacy config, and pre-commit hooks
- Removed the bundled Traefik/Prometheus configs and the standalone Docker workflow; Docker publishing now runs only from the default branch

## 🔒 Security
- **Insult detail visibility**: `GET /api/insults/<reference_id>/` now returns only **Active** insults, plus the logged-in user's own submissions. Pending, flagged, rejected, and removed content now returns `404`.
- **`/metrics` now uses bearer-token auth** (compared with `hmac.compare_digest`) instead of an IP allowlist. If no token is set, the endpoint denies every request.
- The admin site moved from `/admin/` to `/ops-gateway/`, which is less likely to be targeted by automated scanners
- Email templates now escape user-supplied content
- Fixed a CodeQL finding where an exception message could leak internal details to users
- Removed hardcoded Doppler token and database credentials from the dev container config
- Security updates to dependencies, including gunicorn 26.x, cryptography, requests, pyjwt, urllib3, idna, pygments, and Django

## 📦 Deployment
- **Python 3.14** is now required (`>=3.14,<3.15`)
- **Django 6.0.8** (from 5.2.x) and **Django REST Framework 3.18.1**
- Dependency management moved from **Poetry to uv**. `poetry.lock` and the root `requirements.txt` are replaced by `uv.lock` and `requirements/{base,dev,test}.txt`.

- Dockerfile now installs from `requirements/base.txt` and runs through Doppler
- Static and media storage backends moved to `common/storage_backends.py`

## ⚠️ Known Limitations
- Email delivery depends on `django-mailer`'s queue; emails wait until the queue is processed
- LaunchDarkly session replay and observability only run when `LAUNCHDARKLY_ENABLED=true`
- The GraphQL schema may still change in future minor releases

---

## 💥 Breaking Changes
- **Admin URL**: `/admin/` → `/ops-gateway/`. Update bookmarks, runbooks, and any reverse-proxy rules.
- **Metrics auth**: `PROMETHEUS_ALLOWED_HOSTS` has been removed. Prometheus must now send `Authorization: Bearer <METRICS_SCRAPE_TOKEN>`.
- **Insult visibility**: API clients can no longer fetch non-Active insults by reference ID unless they submitted them.
- **Runtime**: Python 3.14 and Django 6.0 are required.
- **Renamed or removed environment variables** (see below)
- **`?category=` on the insult list no longer redirects**: it now filters in place and returns `200`, where before it returned a `302` to `/api/insults/<category>`

## 🔄 Migration Notes
1. **Update environment variables** (Doppler):

   | Removed | Replacement |
   |---|---|
   | `DO_SPACES_KEY` | `S3_OBJECT_STORAGE_KEY` |
   | `DO_SPACES_SECRET` | `S3_OBJECT_STORAGE_SECRET` |
   | `DO_SPACES_BUCKET` | `S3_OBJECT_STORAGE_BUCKET_NAME` |
   | — | `S3_ENDPOINT_URL`, `S3_REGION_NAME` (new) |
   | `PROMETHEUS_ALLOWED_HOSTS` | `METRICS_SCRAPE_TOKEN` |
   | `EMAIL_SSL_PORT` | removed (TLS via `EMAIL_TSL_PORT`) |
   | `NSFW_WORD_LIST_URI` | removed |
   | — | `EMAIL_ASSET_BASE_URL` (new) |
   | — | `LOKI_URL`, `LOKI_PASSWORD` (optional) |
   | — | `LAUNCHDARKLY_SDK_KEY`, `LAUNCHDARKLY_ENABLED`, `LAUNCHDARKLY_OBSERVABILITY_ENABLED`, `LAUNCHDARKLY_SERVICE_NAME` (optional) |

2. **Update Prometheus' scrape config** to send the bearer token:
   ```yaml
   authorization:
     type: Bearer
     credentials: <METRICS_SCRAPE_TOKEN>
   ```
3. **Install dependencies with uv** on Python 3.14:
   ```bash
   uv sync
   ```
4. **Apply database migrations** (`0014`–`0017`: review fields and history tables):
   ```bash
   python manage.py migrate
   ```
5. **Point liveness probes** at `/api/ping/` and keep readiness checks on `/api/health/`.
